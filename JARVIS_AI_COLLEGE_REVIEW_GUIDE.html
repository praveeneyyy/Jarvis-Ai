PART 1 — PROJECT OVERVIEW

JARVIS AI is a hybrid desktop-and-web AI Engineering Workspace designed to assist developers and students with software engineering workflows, real-time code synthesis, automated technical inquiry, and knowledge discovery. Built on Next.js 14 (App Router) and wrapped for desktop execution using Electron 29, the application combines a high-performance Multi-LLM Serverless Cascade (via OpenRouter), real-time live web grounding (DuckDuckGo search scraping), Web Audio-driven 3D neural core visualization (Three.js / React Three Fiber / GLSL Simplex Shaders), and interactive UI widgets including a client-side code execution sandbox.

PART 3 & 4 — PROBLEM STATEMENT & OBJECTIVES

Formal Problem Statement

"To design and develop a resilient, full-stack AI engineering assistant that mitigates developer context switching and AI endpoint downtime by implementing a serverless multi-LLM failover cascade, dynamic real-time web grounding, client-side conversation state persistence, and interactive in-browser code execution."

Primary Objectives

  1. High Availability AI Inference: Ensure continuous uptime by implementing a priority-ordered model cascade across 5 distinct LLM architectures (Llama 3.3, Gemini 2.0, DeepSeek R1, Mistral 7B, Qwen 2.5).
  2. Live Knowledge Grounding: Automatically detect temporal queries and scrape real-time search snippets to eliminate outdated hallucinations.
  3. Interactive Code Execution: Enable in-browser execution of generated JavaScript/TypeScript code directly in the conversation stream without external compilers.
  4. Local State Persistence: Provide instant conversation thread management using browser-local storage with zero external database dependencies.
  5. Audio-Reactive 3D GPU Rendering: Implement custom GLSL Simplex Noise shaders on an icosahedron geometry modulated by Web Audio API Fast Fourier Transform (FFT) frequency bands.

PART 13 — MULTI-LLM FALLBACK CASCADE

To guarantee 100% availability on free tiers without single-provider downtime, the backend server at app/api/chat/route.ts iterates through an ordered priority list of open foundation models:

  1. meta-llama/llama-3.3-70b-instruct:free (Flagship open-weights model by Meta AI)
  2. google/gemini-2.0-flash-lite-preview-02-05:free (Ultra-low latency model by Google)
  3. deepseek/deepseek-r1:free (Chain-of-thought reasoning model)
  4. mistralai/mistral-7b-instruct:free (High-efficiency European open-weights model)
  5. qwen/qwen-2.5-coder-32b-instruct:free (Specialized code synthesis model by Alibaba Cloud)

PART 14 — REAL-TIME WEB GROUNDING

The backend evaluates queries using a regular expression: /search|news|weather|price|stock|today|latest|who is|current/i. When triggered, the server executes an HTTP request to DuckDuckGo's HTML endpoint, parses search result anchors, extracts top snippets, and injects them into the LLM system prompt as real-time ground truth.

PART 15 — 3D WEB AUDIO SHADER CORE

Located in components/voice-orb/, the Web Audio API AnalyserNode performs Fast Fourier Transform analysis on microphone audio (FFT size 512):

  • Bass (0 – 250 Hz): Modulates overall sphere scale and macro pulsing.
  • Mid (250 – 2000 Hz): Drives 3D Simplex Noise surface wave displacement in the GLSL vertex shader.
  • High (2000 – 8000 Hz): Drives particle field turbulence and Fresnel rim lighting glow.

PART 17 — IN-BROWSER CODE EXECUTION SANDBOX

Inside Jarvis/components/CodeBlock.tsx, generated JavaScript/TypeScript code can be executed directly inside the user's browser by clicking `▶ Run`. The component isolates execution using new Function("console", ...), captures console.log output, and renders it in an embedded on-screen terminal console.

PART 23 — STATE & DATABASE ARCHITECTURE

Database Status: The current project does not use persistent database storage (such as PostgreSQL, MongoDB, or Prisma). All conversation threads are serialized to JSON and managed in browser-local storage via lib/chatStore.ts under the key "jarvis_chat_threads_v1".

PART 25 — SECURITY ARCHITECTURE

  • Server-Side API Key Isolation: OPENROUTER_API_KEY is accessed exclusively in app/api/chat/route.ts and is never bundled into client JavaScript.
  • Git Protection: .env*.local is strictly registered in .gitignore.
  • Electron Context Isolation: electron/main.js enforces contextIsolation: true and nodeIntegration: false.
  • External Link Sandbox: Electron intercepts external URLs via shell.openExternal to protect the desktop host.

PART 42 & 43 — TOP VIVA QUESTIONS & CRISP ANSWERS

Q1: What is JARVIS AI?

A hybrid desktop and web AI engineering workspace built with Next.js 14, TypeScript, Three.js, and Electron, featuring a multi-model fallback cascade, live web grounding, and an in-browser code sandbox.

Q2: What is the benefit of the Multi-Model Cascade?

It guarantees near-100% availability on free tiers by automatically catching 429 rate limits or timeouts and falling over to alternative models (Llama 3.3, Gemini 2.0, DeepSeek R1, Mistral, Qwen).

Q3: How does the system handle real-time queries?

The Next.js route handler tests queries with a temporal regex, scrapes live search snippets from DuckDuckGo HTML, and injects those facts into the LLM system prompt.

Q4: How does the 3D orb react to voice?

Web Audio API decomposes microphone input into frequency bins via Fast Fourier Transform (FFT). These frequency values modulate 3D Simplex Noise vertex displacement inside a custom GLSL shader at 60 FPS.

Q5: How does the code runner work?

Inside CodeBlock.tsx, code is dynamically executed using JavaScript's new Function("console", ...) constructor, intercepting console.log calls to display live output in an embedded terminal.

PART 44 — 17 DIFFICULT TRICK QUESTIONS & DEFENSE

Q: Why use an external LLM API instead of training your own model?

Training a 70B parameter model requires millions of dollars in GPU clusters. Our engineering objective was to design the orchestration, real-time web grounding, resilience cascade, and interactive developer environment leveraging foundation models via OpenRouter.

Q: Is an LLM an algorithm?

An LLM is a transformer neural network architecture; our project implements custom algorithms including Web Audio FFT frequency binning, GLSL Simplex Noise vertex displacement, and cascade failover loops.

Q: How do you prevent hallucinations if you don't use a Vector Database?

We prevent temporal hallucinations by dynamically intercepting time-sensitive queries, scraping live search results from DuckDuckGo, and injecting those factual snippets into the LLM's prompt context.
